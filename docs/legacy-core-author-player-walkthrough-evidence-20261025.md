## Provenance/classification policy

- `CREATOR_DESIGN_CLAIM`: maker explicitly states intended rules or purpose. Strong evidence for **intent**, NOT automatic runtime correctness.
- `CREATOR_MECHANISM_DESCRIPTION`: maker explains an implementation step, conditional, timing or expected action. Input to exact original source slice/AST audit, **not** measured execution.
- `PLAYER_OBSERVED_WORKING`: contemporaneous player's alleged completed behavior, weaker than trace; date/version confounded.
- `PLAYER_REPORTED_FAILURE`: observed symptom, **not** proof of root cause unless the author or source independently identifies it.
- `CREATOR_CONFIRMED_DEFECT`: author acknowledges breakage; version-bound and not necessarily present in current pinned copy.
- `INDEXED_VIDEO_DESCRIPTION_ONLY`: search-indexed textual description, not a video transcript or observation.
- `RECONSTRUCTION_HYPOTHESIS`: our candidate graph/AST join inferred from the preceding evidence; neither verified functionality nor owner admission.
- `RELEASE_MISMATCH_RISK`: original v1.4 (June 22, 2015) vs currently listed **v1.4.1** (October 21, 2015) and older May–June reports. Need to identify exact source variant of each report and later verify ZIP membership/content, never assume all 2015 behavior coexisted unchanged.
