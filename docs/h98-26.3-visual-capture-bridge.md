# H98 exact Java 26.3 visual-route evidence correlation (proposed source-neutral bridge)

**Authority:** public [named-place visual harness #36](https://github.com/SupraCraft/mc-server-images/issues/36), [generator benchmark #11](https://github.com/SupraCraft/mc-server-images/issues/11), critic [RDTE #125](https://github.com/SupraCraft/mc-server-images/issues/125), private Lantern playable-story campaign `SupraCraft/mc-structure-foundry-private#19`. DLE = **Durable, Legible, Executable**.

## Why a separate bridge

The Redroof walkthrough reported in #36 previously produced real exact-26.3 server/protocol-777 media/tour artifacts, with multiple views, a grounded walk and public render receipts. That earlier, named structure-exemplar demonstration is not evidence that the private *Lantern at the Gate* story has been played, nor that a stock vanilla client approved it. The current H96/H97 critic PRs use **synthetic** imagery and audio. Source-specific assertions cannot be carried by a model's raw text.

A small adapter in `tools/bridge_visual_capture_claim_h98.py` correlates media bytes to a *proposed* typed route-claim wrapper. It does not implement the canonical `supracraft.visual-route/v0.2` format or amend the existing renderer. It is a stop-gap **claim validator**, not an authority verifier.

### Input contracts
- Media receipt produced by the existing `tools/critic_media_probe.py --kind video --media <actual-public-or-rights-cleared-tour.mp4>` in H96 draft PR #126, with ffprobe-derived tracks/duration and SHA256 of media bytes.
- Proposed `supracraft-h98-tour-claim/v1` JSON with `media_sha256`, `route_contract: supracraft.visual-route/v0.2`, `claimed_server_version: "26.3"`, `claimed_protocol: 777`, SHA256s for route manifest, world, and server proof; an evidence-linked public GitHub Actions run URL; 2–64 ordered view IDs, frame times and finite [x,y,z].
- All such metadata remain **self-reported** until an independent tool retrieves the specified immutable run, artifact, official binary/version receipt, world save and route. A matching SHA inside two user-supplied JSON documents is only internal consistency, not proof either document comes from a legitimate capture.
- Any `human_accepted=true`, `official_client_verified=true`, media runtime verified true, malformed track/time/geography or hash mismatch is refused.

Output: `CORRELATED_SOURCE_CLAIMS_REVIEW_REQUIRED` with precise source links/hashes, `source_run_independently_authenticated=false`, `official_server_verified=false`, `stock_client_verified=false`, `human_story_acceptance=false` and `critic_model_qualified=false`.

## Executable promotion ladder
1. **C0 / schema contract (this PR):** synthetically test matching/mismatching source hashes, exact 26.3 protocol claim, bounded cameras/timestamps and forged authority. Public standard runner, pure stdlib.
2. **C1 / real source ingestion:** after a public, rights-cleared exact-26.3 capture exists, download and rehash actual media, route, server/world receipts from an immutable GHA run. Refuse on expired/missing artifacts. This is **NOT_RUN**.
3. **C2 / production oracle:** independently run the official 26.3 server and prove the exact playable world save was loaded, bot/camera tour followed and output belonged to that world, separately record renderer asset/texture approximation losses. This is **NOT_RUN** for Lantern.
4. **C3 / candidate critics:** give the actual captured media and matched control/reference to qualified independent image/video/audio model candidates. Ground media assertions in bytes/timecode and preserve dissent. **NOT_RUN** for Lantern. H97 SigLIP failed directional tests; CLAP only completed synthetic four-sound recognition.
5. **C4 / physical gameplay and stock-client HIL:** independently verify causal story gameplay/persistence, player traversal, visual recognition and human judgment using the official stock client. **NOT_RUN**; only this may satisfy the Lantern experience acceptance, and no critic can self-promote.
